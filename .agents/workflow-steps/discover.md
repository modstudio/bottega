The requirements are the requester's. Settle what is required before discussing how to build it. Digest the supplied context, inspect enough of the current product to identify where the request lands, and separate observed behavior from assumptions. Ask what outcome evidence each requirement rests on and what evidence would change it. Check that evidence where the project has queryable data. Draft a singular outcome, concrete requirements, verifiable acceptance criteria including rejection and error behavior, and explicit boundaries. Surface contradictions and unresolved questions.

Do not propose architecture or implementation choices in this step. At a level where the agent rules, lock only what the request already settles and record every assumption as an assumption. Ask the operator about anything the request leaves open that changes what the user sees. At a level where the operator rules, present the requirement draft and iterate with the requester. This step is done only when a recorded ruling locks the requirements and boundary.
